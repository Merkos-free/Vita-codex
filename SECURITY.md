# Security / границы доверия

Это персональный экспериментальный клиент, не публичный многопользовательский сервис.

Секреты ChatGPT остаются у официального Codex на ПК. Bridge не читает auth.json/cookies и не имеет OpenAI Audio API. Дочерний процесс запускается argv без shell, API-key переменные удаляются. Локальная установка Codex, PATH, Node.js и конфигурация считаются доверенными; проверка имени npm-пакета не подтверждает издателя.

Сопряжение: шестизначный PIN, 120 секунд, максимум пять попыток, одно устройство. Случайный токен устройства действует 24 часа; в памяти сервера сохраняется хеш. Перезапуск отзывает токены. PIN и токен нельзя публиковать.

Транспорт: HTTP только loopback; LAN требует TLS 1.2+, сертификат и ключ. В общем нативном клиенте реализованы проверка CA/IP, запрет редиректов/прокси и только literal IPv4; реальное устройство ещё не проверено. Browser Origin отклоняется. Нет CORS, raw-RPC, произвольного shell endpoint, отключения TLS или публичного туннеля. Тело запроса ограничено 32 KiB, одновременные соединения ограничены.

Проекты задаются локальным allowlist. cwd возвращаемой сессии должен совпасть с проектом. Это проверка маршрутизации, НЕ доказательство файловой изоляции. Read-only и workspace-write могут иметь доступ чтения за пределами проекта; MCP/плагины официального Codex также нужно проверить отдельно.

Default: read-only + on-request; другие режимы, включая untrusted/unlessTrusted и never, намеренно отвергаются этим клиентом. Явный workspace-write может выполнять допустимые действия без отдельного prompt. Не обещать approve каждого изменения. Проверка схемы не доказывает фактические sandbox-ограничения: до реальных проектов обязателен scratch-test на Windows.

Подтверждения команд/файлов одноразовые и истекают; неизвестные запросы отвергаются. Timeout отправки помечает результат неизвестным, автоматический повтор запрещён. Interrupt и закрытие bridge не откатывают файлы и не гарантируют остановку всех фоновых процессов.

Известные пробелы: не проверены native TLS и reconnect/suspend НА УСТРОЙСТВЕ, effective-permissions smoke-test, аппаратный ввод и голос. Host HTTPS/e2e проверены отдельно, не заменяют аппаратные испытания. Не использовать с чувствительными production-проектами до этих проверок. О проблеме сообщать без токенов, записей голоса и приватного исходного кода.

## Протокол 2 и защита от повторов

Мутации требуют requestId. Журнал 256 операций в RAM привязан к токену, не вытесняет старые IDs; переполнение останавливает новые операции. Ответ сохраняется до отправки по сети. requestStatus только читает результат. При перезапуске токены отзываются; это не глобальное persistent exactly-once. Отсутствие записи/HTTP-ошибка не разрешает автоматическое повторное выполнение.

Клиентские ответы до 1 MiB, JSON depth до 24, 8192 nodes, строка до 256 KiB. Сервер отказывает duplicate JSON keys/nonfinite numbers/дублирующий Authorization. История 64 сообщения/64 KiB UTF-8, без reasoning. Подтверждение только одноразовое, после полного просмотра и удержания кнопки; сервер отдельно проверяет срок и thread.

Setup: только явно заданные private/loopback IP и новая папка. Публичная папка vita содержит лишь CA/адрес/fingerprint; private key остаётся в личном каталоге ПК. Проверить Windows ACL; не добавлять .local в Git, не отправлять private PEM. Сертификат на 30 дней: обновление явно с повторным переносом CA. Нет автоматического firewall/NAT/туннеля.
