# Архитектура

Vita UI -> native HTTPS (ещё не написан) -> Python bridge -> официальный `codex app-server` через stdio -> выбранный проект на компьютере.

Bridge выполняет локальную проверку версии/схемы до открытия порта. Вход ChatGPT проверяет `account/read`. Нет собственного запроса к OpenAI HTTP API. Смена устройства не переносит учётные данные.

Транспорт M0: `GET /healthz`, `POST /v1/pair` с `pin`, `POST /v1/action` с Bearer-токеном и объектом `{operation, data}`. Полный allowlist операций: status, projects, threads, newThread, resume, send, interrupt, snapshot, approval, models. Неподдерживаемые операции не проксируются.

Codex events ограниченно агрегируются в snapshot: текст, статус, turnId, diff, инструменты и ожидающие подтверждения. Ограничение истории не заменяет будущую пагинацию. После timeout send не повторять: состояние unknown требует проверки текущей сессии.

Параллелизм: один изменяющий RPC за раз, snapshots и approvals отдельно; неизвестный server request завершается отказом. Подтверждение расходуется один раз, даже если связь оборвалась при ответе.

UI сейчас полностью offline. Состояния будущей сети: Disconnected -> Pairing -> Ready -> Running/AwaitingApproval -> Completed/Error/Unknown. Только реальное событие меняет состояние выполнения; прогресс в процентах без измеряемого счётчика не показывается.

Следующие риски: совместимость схем отдельных версий, sandbox Windows, suspend/resume, повторное подключение, лимиты JSON/очереди в памяти Vita. На ранней версии не соединять несколько доверенных проектов одновременно и не открывать доступ из интернета.
