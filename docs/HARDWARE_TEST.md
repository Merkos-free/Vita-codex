# Codex Vita 00.11 — первая проверка на устройстве

Это тестовый офлайн-клиент, НЕ готовый пульт Codex. Успешная сборка не доказывает работоспособность на приставке. Результаты пунктов ниже пока неизвестны.

## До установки

Нужна уже настроенная Vita с HENkaku и VitaShell. Не менять прошивку, не ставить дополнительные плагины, не передавать пароли или ключи. Проверить, что ID `CVITA0001` не занят другим приложением: если в `ux0:app/CVITA0001` уже есть неизвестное приложение, не перезаписывать его. Делать резервную копию важных сохранений обычным способом.

Артефакт успешного GitHub Actions содержит `codex-vita-ui-prototype.vpk`, `SHA256SUMS`, `vpk-report.json` и эту инструкцию. SHA-256 относится к VPK, не к внешнему ZIP артефакта. На Windows: `Get-FileHash .\codex-vita-ui-prototype.vpk -Algorithm SHA256`.

Скопировать только VPK в `ux0:data/` через привычный USB/FTP в VitaShell. Открыть файл в VitaShell, проверить имя Codex Vita UI Prototype и установить. Не соглашаться на перезапись другого приложения. Запустить созданную иконку. Для этого теста Windows bridge и аккаунт OpenAI не нужны.

## Проверки (не отмечать без реального результата)

- [ ] Видны иконка/LiveArea, приложение открывается без ошибки; верхний статус OFFLINE / UI PROTOTYPE.
- [ ] Пять вкладок переключаются L/R и касанием; Up/Down прокручивают текст; START закрывает приложение.
- [ ] Кириллица читается, нет квадратов, наложения текста и обрезанных элементов на 960×544.
- [ ] Чат: X открывает системную клавиатуру; ввести `Проверь src/rpc.ts` и подтвердить. Видно тот же текст, он никуда не отправлен.
- [ ] Повторный X открывает существующий черновик; отмена клавиатуры не меняет его. SELECT очищает локальный черновик.
- [ ] Голос: X включает только индикатор уровня; речь двигает индикатор. Запись не накапливается, распознавания нет.
- [ ] Повторный X, смена вкладки и SELECT останавливают микрофон. Он выключается автоматически примерно через 10 секунд активного теста.
- [ ] Сон/возврат и уход в LiveArea не возобновляют тест микрофона автоматически. Это особенно важно проверить на железе.
- [ ] Повторное открытие/закрытие приложения не вызывает зависания.

Если появилась ошибка, не переустанавливать прошивку и не удалять системные файлы. Нужны только её код, экран/шаг и модель приставки. Не прикладывать исходную аудиозапись, логины, токены или личные проекты. Шаблон отчёта — `.github/ISSUE_TEMPLATE/hardware-test.md`.

## Что этот тест не проверяет

Нет связи с Windows, списка настоящих проектов, выполнения задач, diff от Codex или встроенной диктовки. Проверка этих функций — отдельные этапы #3, #4, #5. Даже при удачном аппаратном тесте не считать весь проект готовым.
