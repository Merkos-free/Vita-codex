# Codex Vita 00.20 — отложенная проверка устройства

Это подключаемый тестовый кандидат, НЕ проверенный стабильный клиент. Владелец разрешил отложить этот этап; отсутствие отчёта не блокирует host/CI-разработку. Ни один пункт ниже пока не выполнен на настоящей Vita.

## Установка — только когда владелец решит тестировать

Уже настроенные HENkaku/VitaShell. Никакой новой прошивки или плагинов. Проверить, что Title ID `CVITA0001` не принадлежит другому приложению. 00.20 заменяет наш прежний прототип 00.11; неизвестное приложение не перезаписывать. VPK и SHA256SUMS брать из одного проверенного артефакта.

## Офлайн-проверка

Старт/выход, шесть вкладок L/R и touch, русский текст, прокрутка и focus кнопок. Чат: «Написать» открывает IME; отмена сохраняет старый черновик. Голос: лишь локальный индикатор, не более 10 секунд, без накопления/передачи аудио. Сон/возврат и смена вкладки не возобновляют его автоматически. START закрывает приложение.

## Подключение — только scratch-проект

Сначала проверить официальный Codex и read-only sandbox на ПК. См. README/setup. Только публичные ca.pem и connection.json из подготовленной папки vita переносить в `ux0:data/vita-codex/`. server-key.pem, auth.json и OpenAI credentials остаются на компьютере. Проверить SHA-256 публичного сертификата и LAN IPv4, затем ввести одноразовый PIN.

Проверить отказ неправильного CA/IP/истёкшего сертификата; запрет незапаренного устройства; проекты/новый диалог/историю/черновик; одно задание с учётом лимитов подписки; stop; большие ответы/diff; одноразовые approvals с просмотром полного текста и удержанием X; отзыв токена; Wi-Fi обрыв и SELECT/«Обновить» без автоматического повтора. При неизвестном исходе не отправлять то же задание заново.

Проверить, что реальные ошибки не заменяются fixture-данными. Скриншоты desktop TEST FIXTURE не подтверждают работу Vita. Записать модель приставки/версию, шаги и коды ошибок без логинов, приватного кода и аудио. Не чинить ошибки удалением системных файлов.

Голосовая диктовка, effective permissions и аппаратная производительность остаются отдельными gates #3/#4/#5. При успехе UI-теста не считать весь продукт готовым.
